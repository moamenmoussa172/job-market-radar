About the job

About Mozn

We’re a diverse, collaborative team of innovators united by a shared purpose: to build AI that delivers tangible business value, builds trust, and empowers people and organizations with augmented intelligence. Our culture is built on the relentless pursuit of excellence and meaningful impact.
If you’re passionate about working alongside exceptional talent on world-class AI, and you want the autonomy and runway to do the best work of your career, join us in shaping the future of intelligent enterprises.

About the role

You will be the operational owner for production health of our financial crime intelligence platform: data pipelines (ETL/ELT) and the FCI backend services (APIs, graph/network services and databases). You monitor, triage, diagnose and fix incidents, keep scheduled pipelines running, and turn recurring issues into permanent fixes, runbooks and monitoring. You work directly with fraud investigators, analysts and the customer's IT/operations teams.

What you'll do

  • Monitor daily data pipeline runs (Python/Polars/Pandas scripts, Airflow DAGs, scheduled jobs); detect failures, delays and data-quality problems before users do.
  • Triage and resolve production incidents: read logs, reproduce with sample data, find root cause (schema/dtype drift, corrupt or empty files, upstream delays, memory pressure, SQL errors) and apply or propose a tested fix.
  • Support platform backend (FastAPI services, graph/network API, PostgreSQL, Oracle sources): investigate slow or failing API calls, 5xx errors, memory growth and pod restarts using application logs, request traces and container metrics.
  • Run, re-run and back-fill pipelines safely (full vs incremental loads, dry-run modes, catch-up of missed days) and verify the output.
  • Execute and validate database changes and migrations in UAT and production following the change process, with rollback steps.
  • Operate in containerized environments (OpenShift/Kubernetes, Docker): check pod health, resource limits, environment settings, rollouts and logs using CLI tools, within namespace-level access.
  • Own incident communication: clear status updates, impact assessment and post-incident summaries for business and technical audiences.
  • Write and maintain runbooks, known-error lists and operational checklists; automate repetitive checks and alerts.
  • Reduce alert noise and tune alerting; make sure manual re-runs do not trigger duplicate customer-facing alerts.
  • Work with data engineers and developers to hand over defects with reproducible evidence, and to validate fixes through UAT before release.
  • Support onboarding of new data sources and data requests where operations are involved.
  • Follow security and data-handling rules: least-privilege access, no sensitive data in tickets or logs, approved change windows.

Requirements

  • 5+ years of experience in data engineering, production support, or a similar operations-focused technical role
  • Strong Python skills for ETL development and debugging (Pandas and/or Polars; reading stack traces and fixing data type, schema and null-handling issues)
  • Strong SQL skills (PostgreSQL and/or Oracle): complex queries, query plans, partitioned tables, running and validating migrations
  • Hands-on experience with ETL/ELT pipelines, including scheduling, incremental vs full loads, back-fills and failure recovery
  • Solid understanding of dimensional modeling (star schema, fact and dimension tables) and file formats such as Parquet
  • Experience consuming and troubleshooting RESTful APIs (status codes, latency, authentication, timeouts)
  • Working knowledge of Linux command line, log analysis (grep, jq, tail) and shell scripting
  • Working experience with Docker and containers; basic Kubernetes/OpenShift operations (oc/kubectl: logs, describe, rollout, resource limits)
  • Structured incident handling: prioritisation, root-cause analysis, documentation
  • Strong client-facing and written/verbal communication skills; comfortable explaining technical issues to non-technical users

Nice to have

  • Experience with Apache Airflow or other workflow orchestration
  • Knowledge of backend system and basic API development; understanding of OpenTelemetry-style tracing and structured JSON logs
  • Experience with diagnosing memory or performance issues in Python services
  • Experience with Git and a code review/release workflow; ability to submit small, tested fixes
  • Exposure to graph analysis, fraud, AML or banking data and the investigation workflow
  • Familiarity with monitoring and dashboard tools (Grafana, Prometheus)
  • Exposure to PySpark, message queues or streaming platforms (Kafka, IBMQ)
  • Understanding of data quality frameworks and governance practices
  • Experience with ITSM tooling (ServiceNow, Jira) and SLAs
  • Willingness to join an on-call rota for critical production incidents
